# Officer UX simplification

Focus: judging criterion 2, a usable and trustworthy officer workflow. Evidence visibility and data limitations also support criterion 1.

## Findings and changes

| Area | Problem | Change |
| --- | --- | --- |
| Navigation | Seven equally prominent destinations, including developer states | Four daily tasks: Start, Ondernemingen, Te beoordelen, Mijn beoordelingen. Map and data information are secondary. Developer states remain directly routable. |
| Start | Hero, four statistics, two charts, queues, streets and history compete | One search, street shortcuts and one pending-review task. |
| Search | Global command search and a second table search are confusing | One labelled search per screen. Required seven evidence columns remain. |
| Tables | Checkboxes, column configuration, filter builder and page-size controls imply spreadsheet work | Remove selection and column controls; put simple filters behind a disclosure. Show pagination only when needed. |
| Review | Many approve/reject buttons compete before evidence is read | Readable proposal entries, each with one button to inspect evidence. |
| Record | Side-by-side detail squeezes the table and appears below it on phones | Focused, dismissible sheet. Evidence first, expandable registry/contact details, explicit decisions below. |
| Decision | Technical wording and unclear completion | Plain Dutch confirmation, visible saved state, history link, no duplicate decision controls. Demo/session limitations remain visible. |
| History | A registry number is hard to recognize | Show business name and address alongside decision, evidence, officer, time and reason. Download remains available. |
| Map | Too many controls and technical failure messages | Optional filters, plain-language loading/error states and expandable explanation. Distinguish an unavailable source from no matches. |
| Data information | Technical configuration language and a non-editable field that looks editable | Plain municipality display, source roles and expandable limitations; licence link retained. |

## Verification

- Web TypeScript and ESLint checks passed.
- Production Next.js build passed.
- Existing map/core evidence and scoring tests: 24 passed.
- Browser walkthrough used the actual UI components and existing demo data in a temporary isolated preview, with a test router and no authentication changes.
- Verified street search, optional confidence filter, pagination, empty-result recovery, evidence sheet, explicit confirmation, saved history and pending-count update. Verified cancelling a rejection leaves the proposal undecided.
- Checked review and confirmation at 390px width. Checked map loading and unavailable-data behavior with an intentionally failing test data adapter.
- Authenticated app integration and live map records were not verified: localhost:3000 requires user sign-in. No real officer decisions or external messages were submitted.

The browser tour caught an automatic pagination reset; stable filtered data and explicit pagination handling fix it. A shared TypeScript runtime import also blocked Next.js compilation; its path now matches the package's extensionless bundler imports.
